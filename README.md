# Triple A Super Chatbot

A retrieval-augmented chatbot that answers advisers' questions about superannuation
fund documents. Django + Django REST Framework backend, hybrid (dense + BM25)
retrieval on Pinecone with a BGE reranker, answers generated by a local Ollama model,
and a single-page UI (`mvp_demo/index.html`) with per-adviser sign-in.

## Layout

    mvp_demo/
      config/          Django settings, URLs, WSGI
      rag_api/         API: chat, sign-in, users/funds, document upload + ingestion
      chunking/        PDF text/table extraction, header- and layout-based chunking, TOC filtering
      ocr_solution.py  PaddleOCR path for scanned PDFs
      ingest.py        Offline CLI that chunks PDFs and loads them into Pinecone
      bm25_encoder.json  Fitted BM25 encoder, loaded at startup
      index.html       Front end, served at /
    deploy/            EC2 deployment (systemd, nginx, TLS, DuckDNS) - see deploy/README.md
    docs/              Handover notes: decisions, what we tried, known issues - start at docs/README.md

## Running locally

### Prerequisites

- Python 3.12 or newer (Django 6.0 needs 3.12+)
- [Ollama](https://ollama.com) installed and running (`ollama serve`)
- A Pinecone API key and an index that has been filled by `ingest.py` (see
  [Ingesting documents](#ingesting-documents)). The app connects to Pinecone when it
  starts, so it won't start without a valid key.
- About 4 GB of free RAM: the BGE embedder and reranker are loaded at startup, and
  are downloaded from Hugging Face on the first run

### 1. Install

    git clone --branch handover/fit-4002-chatbot https://github.com/sheharahewawasam/Triple-A-Super_Chatbot.git
    cd Triple-A-Super_Chatbot/mvp_demo
    python3.12 -m venv .venv
    source .venv/bin/activate              # Windows: .venv\Scripts\activate
    pip install --upgrade pip
    pip install -r requirements.txt

On Linux without a GPU, run `pip install torch --index-url https://download.pytorch.org/whl/cpu`
before installing the requirements, to avoid downloading the ~2.5 GB CUDA build.

### 2. Configure

    cp secrets.env.template secrets.env

Edit `secrets.env`:

    PINECONE_API_KEY=<key>
    PINECONE_INDEX_NAME=<index>
    DJANGO_SECRET_KEY=<any long random string>
    DJANGO_DEBUG=True
    DJANGO_ALLOWED_HOSTS=localhost,127.0.0.1

Without `DJANGO_SECRET_KEY`, settings fall back to an insecure development key.
Always set it anywhere other than your own machine.

### 3. Set up the database and model

    python manage.py migrate               # creates db.sqlite3 and adds the advisers and funds
    ollama pull qwen3:1.7b                 # or another model, set with OLLAMA_MODEL

The migrations create adviser accounts with unusable passwords on new installs.
Provision a unique password for every account before sign-in:

    python manage.py changepassword <username>
    python manage.py createsuperuser

Existing databases that previously used the shared placeholder are not rotated by
this source change. Rotate passwords on **each** deployment and record completion
in [the security handover checklist](docs/handover-status.md).

### 4. Run

    python manage.py runserver

Open http://localhost:8000, sign in, and select funds from those assigned to the
account. Identity comes from sign-in; there is no adviser-impersonation selector.

### Troubleshooting

- `No API key provided` / `401 Invalid API key`: `secrets.env` is missing, misnamed, or
  has a wrong Pinecone key. It must be at `mvp_demo/secrets.env`.
- The chat times out or errors: make sure Ollama is running and that the model is pulled
  (`ollama list`).
- `DisallowedHost`: add the hostname to `DJANGO_ALLOWED_HOSTS`.

## Ingesting documents

Fund documents are confidential and are not in this repository. Place them in a
`pdfs/` folder next to `mvp_demo/` (ignored by git), adjust the document list at the
top of `mvp_demo/ingest.py`, then run `python ingest.py` from `mvp_demo/`. Scanned PDFs
need PaddleOCR:

    python -m pip install paddlepaddle==3.3.0 -i https://www.paddlepaddle.org.cn/packages/stable/cpu/
    python -m pip install "paddleocr[all]"
    python -m pip install pymupdf ollama

Uploads are enabled by default; `DOCUMENT_UPLOADS_ENABLED=false` makes the server
read-only. OCR defaults to enabled but can be disabled with `OCR_ENABLED=false`;
install native OCR packages only on a suitably provisioned host. Model names can
be set with `OLLAMA_VLM_MODEL` and `OLLAMA_CLEANUP_MODEL`.

## Tests

### Unit tests

    cd mvp_demo   # skip this if already in mvp_demo
    RAG_OFFLINE=1 python manage.py test rag_api -v 2

On Windows PowerShell, set `$env:RAG_OFFLINE="1"` before the test command.
Offline mode skips Pinecone and BGE loading; it must not be used for live evaluation.

The 37 tests in `rag_api/tests.py` and `rag_api/test_handover.py` cover sign-in,
fund/ownership access, cache scope, throttling, citation grants, dates, seed passwords
and optional OCR imports. Run it after any change to the code, and after
bumping a pin in `requirements.txt`.

### Evaluation scripts

These run against real data, so they aren't part of `manage.py test`. Run each one from
`mvp_demo/` with `secrets.env` in place.

| Script | Checks | Needs |
|---|---|---|
| `python eval_retrieval.py --verbose --require 8` | Retrieval recall: whether the fact that answers each adviser question reaches the model | The Pinecone index populated by `ingest.py` |
| `python -u Grader.py` | End-to-end answer quality, graded by an LLM; writes `currentVersionEval.txt` | The Pinecone index, Ollama running, and `pip install ollama` |
| `python chunk_structure_metrics.py --all-pdfs` | Chunk structure: headings found, section sizes, TOC filtering | PDFs in `../pdfs/`; reports go to `test_chunking_output/reports/` |
| `python validate_evaluation_dataset.py` | That each excerpt in `chunk_evaluation_dataset.json` matches the extracted text exactly | `../pdfs/SIS Act -1.pdf` |

Run `eval_retrieval.py` before and after any change to chunking, ingestion or
retrieval: a chunking change can make part of the corpus unreachable while every unit
test still passes.
